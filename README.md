## ファイルと管理項目

| ファイル | 内容 |
| --- | --- |
| `data/posts.json` | 投稿ID `id`、番号 `number`、投稿日 `publishedAt`、表示順 `displayOrder`、公開状態 `status`、タイトル・カテゴリ・表紙・商品IDの順序 |
| `data/products.json` | 商品ID、正式なブランド名・商品名、説明・出典、SNS紹介画像、許諾を確認する写真欄、公開状態、販売先別のアフィリエイトURL |
| `data/settings.json` | サービス指定の追加広告文言 `programDisclosures` |
| `data/pending-links.json` | 誤商品に向く提供リンクの確認待ち記録（本番ビルドには含めない） |
| `affiliate/*.html` | 所有者提供の楽天画像付き広告タグ。発行タグ本体は編集しない |
| `assets/creative/` | SNS用表紙・紹介ビジュアル・AI背景・装飾（商品写真と別管理） |
| `assets/photos/` | 許諾確認済みの商品写真を後から追加する場所 |
| `content-model.js` | 日付／手動順・検索・カテゴリ・画像パスの共通処理 |
| `publication.js` | 表示可能な商品・リンク・写真の判定 |
| `editor.html` | iPhoneで更新JSONを作成する補助画面 |

投稿は **displayOrderの大きい順 → publishedAtの新しい順 → 投稿番号の大きい順**。手動順は投稿日より優先します。`displayOrder` をすべて0にすれば日時順になります。未設定の旧データにも対応します。

投稿を非公開にする場合は `status: "draft"` または `isPublic: false`。商品も `draft` または `isPublic: false`／`enabled: false` で非公開です。独立して公開している商品は、特集が非公開でも商品一覧に残ります。両方を隠したい場合は商品側も非公開にします。

### 商品の公開状態

- `draft`：下書き。配信データから除外。
- `listed`：紹介のみ公開。公開仕様の出典・確認日が必要。販売リンクなしでも紹介カードを掲載し、「販売リンク準備中」を表示。写真の利用確認が不足している場合、その写真は表示せず「画像準備中」にする。
- `published`：確認済み販売リンクが1件以上あり、商品写真の許諾または提供SNS画像の使用確認、公開仕様の出典が揃っている商品。従来の厳密な公開判定を維持。

SNS紹介画像は `presentation` に登録し、実商品写真の `photo` と混同しません。所有者の指示で使用する紹介画像は `source: "user-supplied-social-artwork"` と `approvedForSite: true` を設定します。

## iPhoneで新しい投稿・商品を追加する

### 方法A：Codexに依頼

次をまとめて渡してください。

- 投稿番号・タイトル・カテゴリ・実際の投稿日（未定なら未定）
- 完成した表紙と商品紹介画像
- SNSと同じ商品順、正式なブランド名と商品名
- 確認できるメーカー仕様の参照先
- 発行済み楽天／Amazonリンク（未設定なら空欄）
- 公開か下書きか、先頭に置くかなど表示順の希望

例：「投稿#02『外出先で役立つ小物3選』を追加。カテゴリは便利グッズ、投稿日は実際の投稿日を指定。画像は添付順、購入リンクは準備中、最新として公開」と伝えるだけで、JSONと素材を追加できます。実際の投稿日・仕様・許諾は未確認の値で埋めません。

### 方法B：iPhoneの追加画面

1. `/editor.html` をSafariで開く。登録済みの商品は選択欄から読み込めます。
2. 下書きも保持する場合、GitHubの最新 `data/products.json` と `data/posts.json` を両方ファイルとして取得し、読み込み欄から取り込みます。自動読込は配信済みデータのみです。
3. 商品名・ブランド・紹介文・仕様出典・確認日を入力。画像は `photoSrc` に許諾確認済み写真、またはSNS紹介画像欄に `assets/creative/...` のパスを入力。未登録画像なら空欄で構いません。
4. 写真を使う場合のみ出典・条件URL・許可範囲を記録し、商用／サイト掲載の許可を確認。SNS画像はサイトへの使用確認欄をチェックします。
5. 投稿番号、ID、タイトル、カテゴリを入力。番号が既存なら同じ特集に追加、商品IDが既存なら商品を更新。`productIds` はSNSの登場順にカンマ区切りで指定します。
6. 表示順の空欄は既存値を保持、新規は現在の最大値より10大きい値で先頭に追加します。日時は実際の投稿日時が分かるときだけ設定。
7. 「紹介のみ公開」か「下書き」などを選び、更新ファイルを作成。`products.json` と `posts.json` を保存してGitHubの同名ファイルを更新。
8. 写真・SNS画像をGitHubの対応するフォルダへアップロード。Cloudflareのビルド完了後、`/#/posts/02` を直接開き、順番・検索・画像・リンクを確認します。

入力データは端末内に保存・復元・削除できます。外部への送信や自動公開はありません。編集画面は認証付きCMSではなくJSON生成ツールで、他の人が開いてもサイトを書き換える権限はありません。

### ファイルを直接編集する記入例

`data/posts.json` の特集1つ分 `{ ... }` を複製して次の項目を変更。配列内の隣の項目とはカンマで区切り、最後にカンマを付けません。

```json
{
  "id": "new-items-3",
  "number": "02",
  "publishedAt": null,
  "displayOrder": 110,
  "status": "published",
  "isPublic": true,
  "title": "外出先で役立つ小物3選",
  "category": "便利グッズ",
  "subtitle": "気になるアイテムをチェック。",
  "cover": "",
  "snsImage": "",
  "coverFit": "contain",
  "productIds": ["new-item-01"],
  "videoUrl": ""
}
```

表紙未登録なら空欄で「画像準備中」を表示。サイト用表紙とSNS縦長原稿は別々に設定でき、文字入り画像は `contain` で全体表示します。`creativeAssets.cover` があるときはそれを優先するため、差し替え時は同じパスにします。

`data/products.json` は商品1つ分を複製し、ID・ブランド・商品名・カテゴリ・説明・画像・出典を書き換えます。同じ商品を別投稿で紹介する場合は複製せず同じ商品IDを参照します。楽天・Amazonは `merchants` 配列に個別設定。未発行URLは `""`、未確認は `verified: false` とし、架空リンクや普通の商品URLで埋めません。

```json
"merchants": [
  { "name": "楽天市場", "affiliateUrl": "", "verified": false, "renderMode": "url" },
  { "name": "Amazon", "affiliateUrl": "", "verified": false, "renderMode": "url" }
]
```

発行済みURLをそのまま保存し、パラメータの追加・削除・短縮・再エンコードをしません。`renderMode: "url"` はその形で利用を許可されているテキストリンク用です。提供HTMLを勝手にテキストリンクへ変換しないでください。

## 楽天広告タグの扱い・現在の未完了事項

提供された6商品の画像付きHTMLを、独立した `affiliate/*.html` として保存。商品カード内に発行タグを最初から表示し、広告内のリンクから楽天へ進めます。表示のための追加タップは不要です。スマホ用の枠の側で全体を縮小し、発行タグ本体・画像URL・商品テキスト・ボタンを改変していません。「広告を大きく開く」も用意しました。タグ内のキャンペーンや店舗の商品名は提供元の広告表示で、サイト独自の評価ではありません。期限経過時は広告タグをサービス上で再発行して差し替えてください。

**直接タップで楽天へ進む独自ボタンにするには、楽天側で「テキストのみ」のリンクを発行してください。** 画像付きタグからURLだけを取り出して独自ボタンへ置換していません。ガイドライン： https://affiliate.rakuten.co.jp/guideline/rule/ ／ https://plaza.rakuten.co.jp/affiliatestaff/diary/201901290000/

Aíamは追加提供されたチャプター65用のタグ（商品ID 10000020）を登録済みです。以前のチャプター8のタグは使っていません。AHRESは販売ページで #SAYU の種類・容量を確認します。Amazonリンクは未提供のためボタン非表示。

商品説明はメーカー等の公開情報を短く要約し、出典と確認日を商品カードに掲載。実際の使用感・効果・価格・レビュー・ランキングを創作しません。商品写真は許諾記録があるものだけ表示し、写真全体を保って文字を外側へ配置。AI素材を写真へ合成したり、実物の色・形・機能を変えたりしません。SNS掲載の許可はサイト掲載と別に確認します。

### SNS運用例

投稿の冒頭画像・動画内の読める位置に「広告・アフィリエイトリンクを含みます｜投稿 #01」、末尾に「プロフィールのモノシルベ → #01で検索」と表示。SNSとサイトで同じ番号を使います。サイト上部にも広告・PR表記を維持し、プログラム指定の追加文言は `data/settings.json` に設定します。

## ビルド・公開設定

```sh
npm run check
npm test
npm run build
```

Cloudflare Pages：ブランチ `main`、フレームワークなし、ビルド `npm run build`、出力 `dist`、ルート空欄。`dist` の配信データから下書きと確認待ちリンクを除外します。

手元の確認は `python3 -m http.server 3000 --directory dist`。iPhoneだけならGitHubへのコミットとCloudflareの自動ビルドで運用できます。`/demo.html` の既存サンプルも維持しています。任意のMP4は表紙の再生ボタンを押してからロード。URLの検索パラメータ（UTM等）は変更しません。
